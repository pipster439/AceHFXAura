## Remaining technical review and acceptance risks

These refine the approved architecture direction; they do not reopen or expand the initial scope above.

| Review area | Baseline direction | Consequence / validation needed |
| --- | --- | --- |
| P0: trigger truth and event fidelity | State is level eligibility; rising needs an observed valid false→true; events use ordered detector batches, not pulse booleans. Missing/stale stays unknown under NOT. | Test 3000/3001 ms boundary, recovery baseline and consistent snapshot reads. Same-packet event AND means co-occurrence. Telemetry can aggregate kills, so detector occurrences are not a lossless gameplay log. Old rules keep old semantics. |
| P0: Replace and blending | Replace means full RGB coverage including black; Overlay preserves black transparency. Alpha crossfades current lower frame; Additive saturates current lower frame. | Replace+Additive is visually equivalent to Overlay+Additive in RGB. Exclusive replacement/muting lower layers is not proposed and would need a different model. |
| P0: layer ordering and compatibility | New rules: base → persistent → transient; priority/order/instance sequence break ties within class. Keep legacy single group, placed between new persistent/transient groups in mixed configs. | Explicit migration needed to adopt new ordering; no silent reordering of legacy-only configurations. |
| P0: native lifecycle and ABI | Optional lifecycle revision 1 + finished/opacity C exports, pinned to the same DLL generation as Effect; no virtual methods. Normalize absent/1/0x00010000 to v1.0, reject other versions. | Current loader merely logs versions, so unknown-version rejection tightens behavior. Correct old v1 and Studio DLLs remain supported. Native corruption/hangs cannot be contained by a lifetime watchdog. |
| P1: one-shot ownership | Capable Effect owns timing, opacity and completion. Old DLLs use exact legacy envelope; old Studio sequences remain looping until explicitly republished as one-shot. | No automatic terminal-sequence conversion, no double application of fade. Default safety watchdog 5 s, configurable up to 60 s for new one-shots; legacy durations preserved. |
| P1: retrigger policy/bounds | Initial default restart with fresh instance; damage/round recommend ignore_while_active; suggested global instance cap 32. | Two kills 300 ms apart re-emphasize flash; damage restart can sustain feedback while events continue. Deferred stack (4/rule) and queue (4 pending/rule, 2 s age) limits remain later-review proposals. |
| P1: reload and scope | Same unchanged rule retains state; changed/deleted rule cancels. Old transients pin old DLL generation; new triggers use new. Base changes reveal newest base. Explicit scope exit/3 s GSI decision staleness cancels scoped feedback. | Foreground loss cancels game-scoped effects; unscoped effects can finish. Continuous layers refresh on recipe/plugin changes. No stale event replay. Future queue/latch rules are documented separately and are not initial requirements. |
| P1: identity and editors | Typed profile_effect/plugin references; builtins and Studio use existing profile recipe keys. Enforce revision-safe rename and guard legacy whole-list saves of unsupported new records. | Names remain identifiers, not rename-proof UUIDs. profile_effect excludes brightness/key overrides like today's overlays. New configs are not guaranteed downgrade-compatible with old daemons. |
| P1: rendering telemetry fallback | Automation's new 3 s decision threshold does not redefine the approximately 10 s connection/status signal or Effect IGsiReader semantics. | Connected-but-stale-for-Automation is a valid state. Existing getters do not automatically hide old values; default masking of rendering input remains a separate future decision. |

Code findings that materially change implementation planning:

- PluginManager does **not** reject Studio's 0x00010000 today; it does no version comparison at all.
- Existing overlays already support state lifetime, per-binding factories and event-sequence retriggering, but coalesce multiple unseen sequence changes and hard-gate all overlays to CS2/CSGO.
- Studio sequence end loops back to entry; no completion/opacity exports exist.
- Current config/plugin synchronization clears active overlays. Factory fallback may share a stateful base Effect and can produce profile/plugin name collisions.
- Web config If-Match checks already exist in the inspected snapshot; the historical missing-concurrency-check claim must not be reused as a current finding.

Initial acceptance must additionally demonstrate: rejecting pulse→profile/stack/queue requests; freshness expiration without a new packet; no rising shot on recovery already true; one process/telemetry view even during mid-evaluation updates; admission-time foreground for buffered events; Phase 4 rule visibility/preservation; and no unconfirmed higher-tier shadowing or partial conversion. Queue/latch lifecycle tests are deferred with their implementations.
