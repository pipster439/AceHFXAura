## Aura 键盘灯效五大问题定位与修复（已验证）

### 关键结论：问题 1/3/4 的根因是「运行了过期二进制」，不是源码缺陷
- 二进制取证实锤（grep exe 内字符串）：
  - `G:/Aura/aura_daemon.exe`(03:54) 与仓库根 `aura_daemon.exe`(05:39)：**不含** `WH_KEYBOARD_LL` / `starry_night` / `quicksand` / `raindrop`
  - 新编译 `build/Release/aura_daemon.exe`：**全部包含**（11 种灯效 + 钩子）
- `src/monitor/foreground_monitor.cpp` 于 04:54 编辑，晚于 03:54 那次编译 → 用户 04:49~04:53 的测试跑在无钩子旧 exe 上
- 教训：排查"功能无效"前先比对 exe 时间戳与源码 mtime，并用 `grep -a <特征串> xxx.exe` 验证二进制内容

### 修复清单
1. `web/index.html`：删除 `renderLightingLoop` 里的 `demoList` 自动演练块（问题 2/3 根因，空闲 2s 后循环触发 W/A/S/D/SPACE/Q/E/R/ENTER）；移除 `selectEffect` 中的 `lastUserKeystrokeTime` 预置
2. `web/index.html`：模拟触发开关仅对 `static` 显示；`saveCurrentInputsToProfile` 写
   `prof.analog = (currentEffect==='static') ? isAnalogEnabled : false`（问题 5）
   - **我自己引入又修掉的回归**：最初加「切离 static 强制 `isAnalogEnabled=false`」，
     导致「常亮(开模拟) → 涟漪 → 切回常亮」时用户偏好被悄悄清空。
     正确做法：区分「用户偏好」与「当前生效」——`isAnalogEnabled` 只作跨灯效保留的
     偏好记忆，生效与否由 `analogActive()` = `currentEffect==='static' && isAnalogEnabled` 判断。
     教训：修"状态泄漏"类问题时，别顺手把用户的合法偏好一起清掉
3. `web/index.html`：`loadConfig` 必须先取 `savedAnalog = prof.analog` 再调 `selectEffect`，否则会被 `saveCurrentInputsToProfile` 覆盖（易错点）
4. `include/monitor/key_input_hub.h`：事件队列加上限 `MAX_PENDING_EVENTS=64`，防止非消费型灯效下无界增长
5. `rule_engine.h/.cpp` + `effect_engine.h/.cpp` + `main.cpp`：`MatchProfile`/`active_profile_` 由裸 `const Profile*` 改为 `shared_ptr<const Profile>`，消除热重载 `profiles_ = std::move(...)` 导致的 use-after-free

### 构建环境（重要，易踩坑）

- **MSB6001 "已添加项。字典中的关键字 HTTPS_PROXY/https_proxy"**：环境同时存在大小写变体代理变量，.NET `ProcessStartInfo.get_EnvironmentVariables()` 建大小写不敏感字典时抛异常，CL.exe 根本没启动。解法：`env -u https_proxy -u HTTPS_PROXY -u http_proxy -u HTTP_PROXY -u all_proxy -u ALL_PROXY cmake --build ...`

### 端到端验证（最关键，补上了"钩子注册成功 ≠ 按键能点亮"的缺口）
- `e2e_key_test.py`（新增）：Win32 `SendInput` 注入真实按键，验证
  `SendInput → WH_KEYBOARD_LL → KeyInputHub → Reactive/Ripple → FrameBuffer`
- 手法：`--dry-run` 每秒打印「活跃通道数 N/128」+ 前 4 个非零 LED ID。
  配置 `bg=[0,0,0]`，则空闲阶段 N 必须 0、按压阶段 N>0 且 ID 需与
  `calibrated_keymap.json` 中该键的 `led_id` 精确对应
- 结果 5/5 通过：A→LED11、J→LED59、Z→LED20、SPACE→LED53 全部精确命中；
  ripple 按压峰值 68 通道（涟漪环带）。`J`/`Z` 特意选旧 demoList 外的键，
  直接证伪"其余按键均无响应"
- **坑**：x64 下 `sizeof(INPUT)` 是 **40** 不是 32——union 尺寸由最大成员
  `MOUSEINPUT`(32B) 决定，ctypes 里只放 `KEYBDINPUT`(24B) 会算成 32，
  `SendInput` 返回 0 + `GetLastError=87`，表现为"按键无响应"的**假故障**。
  务必先验证 SendInput 返回值再怀疑产品代码

### 前端状态机验证（jsdom 方案，比浏览器轻且够用）
- `webui_analog_test.js`（新增）：jsdom 加载**真实 index.html 脚本**驱动交互，28/28 通过
- 关键前提：页面**无 canvas**（键盘预览是纯 DOM），jsdom 可直接胜任，无需装 agent-browser
  （后者要下 ~500MB Chromium）
- 打桩要点：`beforeParse` 里注入 `requestAnimationFrame = () => 0`（停掉渲染循环）、
  `fetch` 桩（GET 返回本地配置副本、POST 记录 `window.__lastPostBody` 以校验真正落盘的值）
- 读顶层 `let` 变量要用 `win.eval('isAnalogEnabled')` —— `let/const` 不挂到 window 上，
  但 `function` 声明会，所以 `win.selectEffect(...)` 可直接调
- **又踩一次同类坑**：断言"拨开关后 prof.analog 立即为 true"失败 → 查 `saveConfiguration()`
  (index.html:2188) 发现开关只改内存态，配置由 `saveCurrentInputsToProfile()` 同步，
  保存按钮在 POST 前会调用它。所以产品没错，是我断言了不存在的中间态契约。
  改为断言「同步后」+「实际 POST 的 JSON」，后者才是端到端
- 测试 Web UI 用 `--config <副本> --port 19899`，避免污染真实 config.json；
  **必须用 `curl --noproxy '*'`**，否则沙箱代理会把 127.0.0.1 也代理掉返回 502
- Bash 里 `(cmd &)` 起的进程会随 shell 退出被杀，需长驻的服务要用工具的 run_in_background
