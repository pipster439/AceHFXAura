# Studio Effect workspace safety — CURRENT

The Effect editor accepts the canonical Blockly workspace serializer state, legacy preset block containers and bare block arrays. `workspaceSafety.js` bounds JSON to 256 KiB, 2048 total blocks (including hidden shadows), 48 block levels and a bounded complete object tree. It rejects cyclic/shared objects, unsupported serializer/schema keys, duplicate IDs, unknown blocks and Automation-only nodes before running Blockly serializers.

All effect loads stage in a disposable headless workspace with events disabled. Loaded block count, input names and field names are checked, including inactive fallback shadows. Only a valid candidate replaces the retained editor. Failed live loading restores the prior serialized workspace and history; error propagation is mandatory. Headless preflight is software evidence, not proof of every WebView/SVG failure path.

Effect selection changes name/publication and starts durable observation only after load succeeds. Rejected selection displays the error and retains the existing name/content; no autosave is submitted under the rejected name. Startup failures block draft persistence so the rejected recovery record is not replaced by a blank graph. Opening a valid project or preset clears the blocked state. AI Apply/Undo and durable draft projection use the same validation boundary. Publication references, immutable plugin generations and native draft journals remain governed by the existing [workflow](../studio/STUDIO_WORKFLOW.md).

Tests: `frontend/tests/workspace-safety.test.mjs`, existing Studio/AI/Bundle/Storage/Publication suites. Native WebView 125% DPI and visible recovery acceptance remain Owner checks; headless graph tests do not close those gates.

Blockly 13 serializes an empty workspace as `{}` and can serialize variables or workspaceComments without blocks. These valid roots are accepted by both editor and native draft storage. Workspace comments have a bounded list and validated IDs, text and finite coordinates. The existing byte/tree/block limits still apply. AI snapshot loading uses normalized validated state. `workspace-compatibility.test.mjs` exercises actual serializer output, 2048 legal blocks, presets, shadows, disabled blocks, undo/redo, AI and bundle flows; FirmwareAndWorkspaceCompatibilityTests covers native durable recovery and snapshot/bundle round trips.
