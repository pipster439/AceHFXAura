# M605 firmware admission — CURRENT

Configuration mutation admission lives in `M605Runtime` under DeviceWriteMutex and is repeated by the private native SendReport boundary. It uses trusted BasicInfo acquisition, never client JSON or HIDD_ATTRIBUTES.VersionNumber. Only exact 1.00.59 is supported; Unknown, Unsupported and ReadFailed reject. Persistent quarantine remains authoritative. Configuration reports, reset/restore, DKS, RT, SpeedTap, actuation, deadzone, profile replay and hardware slot selection pass this boundary. Direct RGB C0 81 and read-only BasicInfo 12 00 remain separate.

The vendor USB BasicInfo payload is 64 bytes; Windows uses a 65-byte buffer beginning with Report ID 0. Vendor payload bytes 4/5 are hexadecimal patch/minor; bytes 6/7 are little-endian major. The captured `59 00 01 00` yields 1.00.59. The parser checks exact framing, command 12 00, captured reserved prefix, bank count 6, active slot 1..6 and bounded version encoding. Reserved zero bytes are a captured envelope constraint, not an invented documented status enum. Fixture provenance and 62 historical frames live in `tests/fixtures/m605_firmware_basic_info.json`.

Native acquisition uses the original opened handle, verified M605 identity/MI endpoint, a host session epoch, queue flush, bounded reads, deadline and cancellation drain. Echoes and unrelated frames cannot authorize. Disconnect clears authorization. Configuration submission checks current original handle identity/epoch before writing; runtime serialization prevents concurrent selector/query/stage interleaving. Profile plans additionally check runtime generation between transactions and before success publication. Failure before admission does not arm the persistent latch or update applied shadow; indeterminate stage/apply retains existing quarantine semantics.

**Evidence boundary:** BasicInfo has no wire nonce or transaction ID. Queue flush and host epochs cannot distinguish an identical delayed response to an earlier query on the same opened session. The supported version is an observation of that device session; same-session firmware invariance is an operational assumption, not cryptographic authenticity. Native Win32 read timing, reconnect notifications and acceptance on a real 1.00.59 keyboard remain BLOCKED_PHYSICAL. Offline fixture replay, fake transport and model tests do not establish hardware acceptance. No real HID operation is part of software CI.

Magnetic and Profile status add optional read-only `firmware_compatibility` fields (state, version, reason, session_generation, source). These fields are not configuration and cannot grant admission. Missing fields default Unknown in old status payloads. Firmware Profile refusal has error_code FirmwareAdmissionDenied; clients retain its diagnostic instead of treating HTTP 409 as revision conflict. Disconnected authoring and existing quarantined state retain their earlier semantics.

CTest `firmware_gate` replays the capture fixture, covers positive mutation paths and fault cases, and stresses 400 fake reconnect/lifecycle cycles. `firmware_unknown_seam` checks the default fail-closed transport seam. Magnetic API and Profile/coordinator tests verify no writes, latch arm or false success after refusal. These are VERIFIED_SOFTWARE within the observation contract above.
