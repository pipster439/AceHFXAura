# Stage B/C 待执行验收矩阵

本轮所有实体测试均 **NOT RUN / PENDING**。Computer Use 阶段 B 未恢复；不会主动开启捕获、要求按键或改配置。此表是后续独立测试设计，无真实硬件 fixture。

真值来自用户在专用测试窗口明确选择的实体键/按下释放动作。测试记录只保留 Case ID、计数、判定和聚合时序。先以少量动作确认候选在**既有配置**中自然出现；没有被动报告则停止，不执行使能命令。测试不启动 Aura 的写路径或灯效，不加载 HAL；现有 daemon 不由工具控制。

## 身份与操作矩阵

| Case | 实体动作 | 物理 Provider 必须证明 | 失败/边界 |
|---|---|---|---|
| K01 | A/W/S/D 分别按下释放 | 每个实体 ID 的 Down/Up 可区分 | 仅此通过仍不能证明物理身份 |
| K02 | 左/右 Shift 分别按下/释放，交错重叠 | 两实体 ID 与释放独立 | 不能以同一逻辑 Shift 替代 |
| K03 | 左 Ctrl、左右 Alt | 3个实体 ID 与释放 | 序列/左右身份不清→UNKNOWN |
| K04 | 右 Ctrl 候选键位 | 记录 `RightCtrl/Copilot` 是同一 Wire0040 实体槽；当前校准标签COPILOT | 无另一个独立 R_CTRL 实体时该独立测试 NOT_APPLICABLE，不虚构结果；重映射实验另授权 |
| K05 | 左 Win 独立按下释放 | 独立 ID；不能被 Copilot 过滤 | 宏推断不算物理证据 |
| K06 | Copilot 独立按下、按住、释放 | 只给真实 Copilot ID；逻辑 Win/Shift/F23 不能冒充其它实体 | 候选出现多实体或缺 Up→失败 |
| K07 | 先按住真实 Win，再按/放 Copilot，最后放 Win；逆序重复 | Copilot 释放不清真实 Win，Win 释放不清 Copilot | 时间接近/单设备来源不够 |
| K08 | 左/右 Shift 与 Copilot；Win+Shift+Copilot，全部释放顺序 | 所有真实实体并发保持，不新增宏的实体 ID | 不能将50ms去重当验证 |
| K09 | Fn 单独与 Fn+选定测试键 | Fn 身份及独立释放；组合输出不改变源身份 | 只有逻辑组合输出→物理缺口 |
| K10 | 按住多个选定键，交错释放；含修饰键 | 每实体状态保持，解除任一键不解除其它 | Boot 6KRO 与 MI_03 联合关系需独立记录 |
| K11 | >6个非修饰键 NKRO | 至少7个普通实体 ID 及释放都保持 | 不能用4个字母+修饰键宣称>6非修饰键验证；用户预选额外 Q/E/C 后才扩展白名单 |
| K12 | 选定键快速连按，按住不放，多次相同报告 | 无重复 Down/Up、无卡住；按住时间不等于报告刷新保证 | 保留丢失/未知，不自动补造释放 |
| K13 | 会话启动前已按住选定键 | 可信快照或 Unknown；不能“无事件=全释放” | 仅delta输入没有恢复方式→不满足完整状态 |
| K14 | 有键按住时用户拔插/重连 | 旧会话清除、新 generation、等待基线；不能接受旧报告 | reset 不是物理 Up；未重连验收不称可靠 |
| K15 | 锁屏/焦点丢失/停止/窗口关闭 | 停止监听，注销并清空，零持续采集 | 生命周期未经验证则不运行 |
| K16 | 另一键盘输入、双同型号设备 | 非目标不解析；多个匹配不合并，要求明确绑定 | 不保存其它设备按键/文本 |

## 配置相关的身份对照

| Case | 对照方式 | 物理证据目标 | 本轮边界 |
|---|---|---|---|
| M01 | 利用已经存在的板载重映射配置；若无则保持Pending | 源实体 ID 不跟随输出 usage 改变 | 不发送新 remap 或 Profile switch；后续配置变更需单独明确授权 |
| M02 | 既有 DKS 源键产生多个逻辑动作 | 同一源实体 Down/Up；阶段事件与实体状态分别判定 | `73` 参数1..4 不能先定义为 Press/Release |
| M03 | 既有 SpeedTap/SOCD 对 A/D，按住两键交错释放 | 被逻辑裁决抑制的实体仍为激活 | 单个逻辑 winner bit 不够；没有既有配置则Pending |
| M04 | 既有宏键/WinLock/不同模式下选定键 | 区分物理源与被抑制的逻辑输出 | 不打开模式、不改开关或设备配置 |

这里设计的“稳定源 ID”仅指开关的数字激活状态。RT/Hall 迟滞可能使数字释放发生在手指仍触键时，不能借此推断机械接触或模拟深度。

## 结果准则

- 每用例同时标记观察通道/设备会话、配置来源是否已知、计数和 PASS/FAIL/UNKNOWN/NOT_APPLICABLE；无数据不填 PASS。
- 普通键同名输出只验证送达。需要宏/真实修饰键并发和至少一个既有输出变换对照，才可证明物理源不随逻辑输出变化；无法安排对照时保留 UNKNOWN。
- Host monotonic receipt timestamp 只用于接收间隔/顺序；没有外部接触时间戳时，不宣称物理端到端 latency。API3 gate 开关历史12通知也不是本矩阵按键样本。
- 只有有版本绑定的真实报告证据后，才将匿名选定键报文转成 parser fixture，并与真实录制结果区分；合成 state-machine fixture 不能提升硬件结论。
- 任一必需键身份/Up/启动状态/恢复不可靠，不能给 VIABLE。满足部分逻辑来源过滤可给 PARTIAL，但 Provider 不得标 physical verified。
